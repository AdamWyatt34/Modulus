### Added

- **`ModulusKit.Testing` package**: a companion package for `ModulusKit.Messaging` — module-level integration testing without hand-rolling a fake transport or writing raw outbox/inbox queries. `TestMessageTransport` is a public `IMessageTransport`/`ITransportHealthProbe` implementation built entirely against the public transport SPI (no internals access) that mirrors the shipped in-memory transport's channel-per-event-type delivery, `ScheduledEnqueueTimeUtc` timer delivery, and `MessageDispatchResult.Retry` redelivery (with the same `modulus-delivery-attempt` header and backoff formula), while adding a thread-safe `Published`/`DeadLettered` envelope history, `PublishFailure` exception injection, and typed `PublishedEventsOf<TEvent>()`/`DeadLetteredEventsOf<TEvent>()` helpers. `ServiceCollectionExtensions.AddModulusTestTransport()` swaps it in after `AddModulusMessaging`. `ModulusMessagingTestHarness` starts/stops every registered `IHostedService` in the same order a real host would (consumer host before the outbox processor, reverse on shutdown) and exposes the swapped-in transport directly. `TestWait` ports the library's own polling-assertion helper (with a new async-condition overload). `OutboxTestQueries`/`InboxTestQueries` add `IServiceProvider` extension methods for common outbox/inbox assertions (pending, dead-lettered, drain-wait, per-handler processed) without depending on any particular assertion library. New docs page `docs/testing/modulus-testing.md`; scaffolded `Tests.Integration` projects (both `modulus init` and `modulus add-module`) now reference the package.
